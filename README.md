# Тестовый фреймворк

Каркас для проверки сайта, мобильной версии сайта и приложений iOS и Android.
Сценарии пишутся по-русски. Логины, адреса стендов и база 1С лежат в настройках, не в тексте сценария.

Учебные тесты сайта ходят на публичный магазин [SauceDemo](https://www.saucedemo.com). Его можно заменить на свой адрес.

## Что уже есть

- Сайт в Chrome, Firefox и Safari.
- Тот же сайт в размере телефона: Chrome (Android) и Safari (iPhone).
- Приложение Android и iOS через Appium. iOS запускается только на macOS.
- Переключение стенда: `dev`, `stage`, `prod`. Свой стенд — это новый yaml-файл.
- Сценарии отдельно от кнопок и полей.
- Заготовка отчёта в Testmo.
- Чтение 1С через опубликованный HTTP/OData или через SQL Server только на чтение.

## С чего начать

Нужны [Node.js](https://nodejs.org) 22 или новее и этот проект.

```powershell
npm install
npx playwright install
.\run.ps1 web
```

Первая команда ставит инструменты, вторая — браузеры, третья гоняет учебный вход в магазин в Chrome.
Браузер при этом не показывается. Чтобы видеть его:

```powershell
.\run.ps1 web-headed
```

После прогона отчёт открывается так:

```powershell
npm run report
```

## Как запускать

Команды ниже рассчитаны на PowerShell. Второе слово — стенд. Если его не писать, берётся `dev`.

| Команда | Что делает |
| --- | --- |
| `.\run.ps1 web` | Сайт в Chrome |
| `.\run.ps1 web-headed` | То же, но браузер виден |
| `.\run.ps1 cross` | Сайт в Chrome, Firefox и Safari |
| `.\run.ps1 mobile-web` | Сайт в окне телефона |
| `.\run.ps1 all-ui` | Все браузеры и оба телефона |
| `.\run.ps1 android` | Приложение Android |
| `.\run.ps1 ios` | Приложение iOS, только macOS |
| `.\run.ps1 1c` | Проверяет, что 1С отвечает |
| `.\run.ps1 onec` | Сценарий «контрагент есть в базе» |
| `.\run.ps1 testmo` | Отправляет уже готовый отчёт в Testmo |

Примеры другого стенда:

```powershell
.\run.ps1 web stage
.\run.ps1 cross prod
```

То же самое без `run.ps1`:

```powershell
$env:TEST_ENV = "stage"
npm run test:web
```

## Куда что класть

```text
features/web/            сценарии сайта
features/mobile-web/     сценарии сайта с телефона
features/native/         сценарии приложения
src/steps/ui/            перевод фраз сценария в действия на сайте
src/steps/native/        то же для приложения
src/pages/               страницы сайта: куда нажать и что проверить
src/screens/             экраны приложения
config/environments/     адреса стендов, пользователи, 1С, Testmo
reports/                 результаты для Testmo
.env                     пароли, в git не попадает
```

Сценарий не ищет кнопки сам. Он говорит «входит как standard», а логин и пароль `standard` берутся из yaml стенда.

## Как добавить сценарий

Файл `features/web/корзина.feature` можно назвать и по-английски. Внутри:

```gherkin
# language: ru
@web
Функция: Корзина

  Сценарий: В корзине виден добавленный товар
    Допустим открыта страница входа
    Когда пользователь входит как "standard"
    Тогда он видит каталог товаров
```

Метка в первой строке функции решает, куда попадёт сценарий:

- `@web` — обычные браузеры
- `@mobile-web` — окно телефона
- `@android` и `@ios` — приложение, файл лежит в `features/native`
- `@onec` — отдельный запуск `.\run.ps1 onec`
- `@wip` — черновик, не запускается

Фразы, которых ещё нет, нужно один раз добавить в `src/steps/ui/auth.steps.ts` (или новый файл рядом). Пока фразы нет, прогон остановится и напишет, какой строки не хватает.

Нового пользователя добавляют в `config/environments/dev.yaml`, раздел `users`. В сценарии после этого пишут его короткое имя, например `"cashier"`.

## Как добавить страницу

Новый экран сайта — файл в `src/pages`. В нём только поля и действия. Текст сценария туда не копируют.

Учебный вход разобран на `LoginPage` и `CatalogPage`. Общий кусок шапки лежит в `src/pages/components`. Для приложения тот же приём: экран в `src/screens`.

Поля учебного магазина помечены `data-test`. Для своего сайта в странице меняют именно эти указатели, сценарии не трогают.

## Стенды

Файлы `config/environments/dev.yaml`, `stage.yaml`, `prod.yaml`.
Имя файла и есть имя стенда. Свой стенд: скопируйте `dev.yaml` в `qa.yaml` и запускайте `.\run.ps1 web qa`.

Пароли в yaml не пишут. Вместо пароля указывают имя переменной, а значение кладут в `.env`:

```yaml
users:
  standard:
    usernameEnv: APP_USER
    passwordEnv: APP_PASSWORD
```

Образец переменных — `.env.example`. Скопируйте его в `.env`.

## Браузеры и телефон в браузере

Ежедневный запуск — Chrome. Перед сдачей имеет смысл `.\run.ps1 cross` и `.\run.ps1 mobile-web`.
Телефон здесь не настоящий: браузер сужается до Pixel 7 и iPhone 14. Это проверка вёрстки и сценария, не магазина приложений.

Новый браузер добавляется блоком в `playwright.config.ts`, по образцу `firefox`.

## Приложение iOS и Android

1. Поставьте [Appium](https://appium.io) и драйвер:
   - Android: `npx appium driver install uiautomator2`
   - iOS (только Mac): `npx appium driver install xcuitest`
2. Запустите эмулятор или подключите телефон.
3. В yaml стенда заполните `mobile.android` или `mobile.ios`: пакет, activity или bundle id, при необходимости путь к файлу приложения.
4. В `mobile.selectors` укажите accessibility id полей. Их лучше просить одинаковыми на iOS и Android.
5. Поднимите Appium (`npx appium`) или поставьте `mobile.startAppium: true`, чтобы прогон поднял его сам.
6. `.\run.ps1 android` или `.\run.ps1 ios`.

Пока в yaml учебные `com.example.app`, сценарий приложения не проходит: своего приложения в каркасе нет.

## 1С

Прямая правка базы тестом не делается. Есть два способа читать данные.

**HTTP, его лучше выбрать.** База 1С публикуется, обычно как OData. В yaml:

```yaml
onec:
  mode: http
  baseUrl: http://server/trade/odata/standard.odata
  usernameEnv: ONEC_USER
  passwordEnv: ONEC_PASSWORD
  catalogs:
    counterparty: Catalog_Контрагенты
```

Имя `Catalog_Контрагенты` у каждой базы своё, его видно в корне OData. Логин и пароль — в `.env`.

Проверка: `.\run.ps1 1c`. Сценарий «контрагент есть в базе» — `.\run.ps1 onec`. Пока 1С выключена, этот сценарий пропускается и не красится красным. Имя «Ромашка» в `features/web/onec.feature` замените на контрагента из своей базы.

Если для подготовки данных есть HTTP-сервис 1С, его адрес пишут в `onec.httpServiceBaseUrl`. Вызов из кода: `onec.callService('путь', { ... })`.

**SQL Server, только чтение.** Подходит, если HTTP опубликовать нельзя. Тест умеет выполнять готовый `SELECT` из yaml. Параметр передаётся отдельно, в текст запроса имя контрагента не подставляется. Запрос, который не начинается с `SELECT`, каркас отклонит. Имена таблиц 1С выглядят как `_Reference123` и зависят от конфигурации — их даёт разработчик 1С. Образец закомментирован в `stage.yaml`.

Запись в SQL из этого каркаса намеренно нет.

На `dev` стоит `onec.mode: off`, поэтому обычные тесты сайта базу не трогают.

## Testmo

После тестов появляется `reports/junit-web.xml` (для телефона — `reports/junit-android.xml` и `reports/junit-ios.xml`). Testmo забирает эти файлы.

1. В Testmo создайте API-ключ и положите его в `.env` как `TESTMO_TOKEN`.
2. В yaml стенда укажите адрес `https://компания.testmo.net`, номер проекта и `testmo.enabled: true`.
3. Запустите тесты, затем `.\run.ps1 testmo`.

Отправка идёт официальной утилитой Testmo. Пока `enabled: false`, команда ничего не шлёт и просто пишет, что отчёты выключены.
Имя прогона можно задать на один запуск: `$env:TESTMO_RUN_NAME = "Релиз 1.2"`.

Если результаты понадобится создавать из кода, а не файлом, заготовка клиента лежит в `src/integrations/testmo/client.ts`.

## Как это устроено, коротко

- **Сценарий и страница раздельно.** Сценарий читается как чек-лист. Страница знает поля и кнопки. Экран приложения устроен так же.
- **Стенд подставляется снаружи.** Адрес сайта в тесте не зашит, он берётся из yaml.
- **Общие вещи готовятся один раз.** Окружение, страницы и клиент 1С подключаются в `src/fixtures/bdd.ts`.
- **Пользователь по короткому имени.** Сценарий просит `"standard"`, пароль лежит в настройках.
- **1С и Testmo спрятаны за своими клиентами.** Сценарий не собирает адрес OData и не знает адрес Testmo.

## Частые сбои

- `Нет окружения` — опечатка в имени стенда или нет такого yaml.
- `Нужна переменная APP_USER` — для stage/prod не заполнен `.env`.
- Браузер не скачан — выполните `npx playwright install`.
- Фраза из сценария не найдена — добавьте её в `src/steps`.
- Android не стартует — не запущен Appium, эмулятор или в yaml пустой пакет приложения.
- iOS на Windows не запустится, нужен Mac.
